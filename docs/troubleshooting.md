# Troubleshooting

| Message or symptom | What to do |
| --- | --- |
| `Branch <name> is already checked out in <path>` | That worktree, or your main checkout, already has the branch. Work there instead, and run `ddev fire-worktree-start` in it if it has no site yet. |
| `Branch <name> is checked out in <path>, which no longer exists` | A tool deleted the worktree's directory without telling Git. Run `git worktree prune`, then `ddev fire-worktree-prune` to delete its DDEV project. |
| `Branch <name> already exists and doesn't have pull request #<n>'s latest commit` | Your branch has diverged from the pull request, for example after a force-push. Pass another branch name, `ddev fire-worktree-create --pr=<n> review-<n>`, or delete the old branch. |
| `Couldn't fetch pull request <n> from origin` | origin has no pull request with that number. `--pr` needs origin to be the GitHub repository the pull request is in. |
| `Couldn't look up pull request <n> with gh` | Sign in with `gh auth login`. Until then the branch is named `pr-<n>`, and `--base` doesn't work. |
| `Couldn't snapshot <project>` | Startup used the last worktree copy instead, or the newest other snapshot if there's none. Start your main checkout with `ddev start`, or use `--db=fresh` or a SQL dump. |
| `No earlier worktree copy to reuse` | `--db=latest` found no `fire-worktree-seed-*` snapshot, so it used the newest other snapshot it names. If that's the wrong data, run `ddev fire-worktree-refresh --db=primary` in the worktree. |
| An agent tool says only that its setup script failed | Read `.ddev/fire-worktree-start.log` in the worktree. Each start adds its output there. |
| `The worktree is running, but the build failed` | The site is up with the copied database, at the URLs printed above the message. Fix the error, then run the command it prints. Rerunning startup doesn't rebuild. To have startup and refresh exit 0 when the build fails, set `WORKTREE_BUILD_FAILURE=warn`. |
| `WORKTREE_BUILD_FAILURE must be fail or warn` | Fix the value in `.ddev/config.yaml` or `.ddev/config.local.yaml`. |
| `The worktree is running, but the import failed` | The site is up, but its database is empty or partly imported. Fix the dump, then run the `ddev import-db` command it prints. |
| `This worktree has no database of its own yet` | `refresh` only replaces a database that startup gave the worktree. Run `ddev fire-worktree-start`, which copies one in. |
| `Database:  none yet` | `info` found no database, as after `ddev fire-worktree-remove --keep-checkout` or `ddev delete`. Run `ddev fire-worktree-start`, which copies one in. Don't run `ddev start` first: it creates an empty database, which startup then keeps. If you did, run `ddev fire-worktree-refresh`. |
| `If the error is about mounting <path>, set WORKTREE_MOUNT_GIT=false in web_environment and rerun.` | `ddev start` failed, and startup had mounted the shared Git directory, `<path>`, in the web container. If Docker says `bind source path does not exist`, your main checkout has moved: run `git worktree repair` from the main checkout, then `ddev fire-worktree-start` in the worktree. If Docker can't mount that path, set `WORKTREE_MOUNT_GIT=false` in `web_environment` and rerun `ddev fire-worktree-start`. See [Git in the web container](how-it-works.md#git-in-the-web-container). |
| `ddev start failed, and the worktree's database may be empty` | `refresh` deleted the old database, but DDEV couldn't start with the new one. Fix the error, then run the command it prints. |
| `Waiting for another worktree to finish starting` | Another worktree is running `ddev start`, for a start or a refresh. A lock left by a crashed run is cleared automatically. |
| `Timed out waiting for ~/.ddev/fire-worktree-start.lock. Delete it if no other worktree is starting.` | A start or refresh has held the start lock through `ddev start` for 30 minutes. If no worktree is starting or refreshing, delete the directory it names. |
| `Timed out waiting for <main checkout>/.git/fire-worktrees.lock. Delete it if no other fire-worktree command is running.` | A fire-worktree command has held the registry lock, which guards `.git/fire-worktrees`, for 30 seconds. If none is running, delete the directory it names. |
| `This worktree inherits <NAME>=<url> from web_environment` | That value names your main checkout's site, so the worktree uses it too. Build it from `${DDEV_SITENAME}.${DDEV_TLD}` or `$DDEV_PRIMARY_URL`. See [Drupal notes](drupal.md#drupal-notes). |
| `reads Git metadata that a worktree's container can't read` | Your settings read `.git/HEAD` or run `git`, for example to show the branch in the environment indicator. In a worktree, `.git` is a file, so `.git/HEAD` can't be read, and Drupal prints PHP warnings on every page and Drush command. `git` works in the container, so get the branch from `git branch --show-current` instead, or skip that code when `.git/HEAD` isn't a readable file. With the Git mount off (`WORKTREE_MOUNT_GIT=false`, or DDEV's global `no_bind_mounts`), `git` fails too, with `not a git repository`. The warning names the file and line when Drush's output shows them. See [Drupal notes](drupal.md#drupal-notes). |
| Git in the web container says `detected dubious ownership in repository` | A `.gitconfig` in `.ddev/homeadditions` or `~/.ddev/homeadditions` replaces DDEV's, which has `safe.directory = *`, so Git refuses the mounted worktree. Add `directory = *` under `[safe]` in that file, then run `ddev restart`. |
| Git in the web container says `unknown repository extension` | Your host's Git uses a feature the web image's older Git can't read, such as `worktree.useRelativePaths`. Turn that feature off, or set `WORKTREE_MOUNT_GIT=false` in `web_environment` and rerun `ddev fire-worktree-start`. See [Git in the web container](how-it-works.md#git-in-the-web-container). |
| `Couldn't create a login link` | `ddev drush uli` failed, and the warning shows the first line of Drush's error. For example, Drupal isn't installed in the worktree's database, or a table such as `users` is missing from an incomplete copy. Run the command it prints to see the whole error. For a database from `--db=fresh` or a SQL dump, which may still be empty, it prints how to populate the database instead. |
| `The database copy looks incomplete` | The new copy has no tables, or Drush can't bootstrap Drupal from it, as when a restore stops partway. Startup skipped the build and left the site running. Run `ddev fire-worktree-refresh` for a new copy, which it builds. If the source database is itself empty or broken, fix it first, or choose another with `--db`. |
| `This worktree's database has no tables` | Startup kept a database that's empty, such as one `ddev start` created after `ddev fire-worktree-remove --keep-checkout`. Run `ddev fire-worktree-refresh` to copy one in. |
| `has a label longer than 63 characters` | Shorten `WORKTREE_NAME_PREFIX` or the worktree's directory name. |
| `Refusing to overwrite .ddev/config.worktree.local.yaml` | You or another tool wrote that file. Move its settings to `config.local.yaml` and delete it. |
| `Startup created untracked files that nothing ignores` | `ddev composer install` or the build wrote the listed files, and no `.gitignore` hides them, so `ddev fire-worktree-remove` refuses the worktree until they're gone. The site still started. If every checkout makes these files, list them in the project's `.gitignore`. |
| `Refusing to remove ...; commit, stash or discard these changes first` | Commit, stash or delete the listed files, or use `--keep-checkout` to delete only the DDEV project. If they're Drupal scaffold files, such as `web/README.md`, in a worktree an earlier version started, run `ddev fire-worktree-start` first. See [Drupal notes](drupal.md#drupal-notes). |
| `Pass --yes to confirm when not running interactively` | Add `--yes` when no one is at the terminal to answer the prompt. |
| A worktree has old data | Its database was copied when it was created; `ddev fire-worktree-info` shows when. Run `ddev fire-worktree-refresh` in it for [a new copy](databases.md#when-the-database-is-copied). |
| Search finds nothing in a new worktree | Its search server starts empty, but the copied database marks items as indexed. Run `ddev drush search-api:reset-tracker`, then `ddev drush search-api:index`. See [Search](drupal.md#search). |
| `ddev fire-worktree-prune` lists volumes an earlier prune left behind | Versions up to 0.1.1 didn't delete add-on services' volumes, such as `ddev-<name>_solr`. If no other clone uses the project, delete them with `docker volume rm`. |
| The computer slows down with several worktrees | Each running worktree uses its own containers. `ddev fire-worktree-list` shows which are running; `ddev stop` the idle ones. |
